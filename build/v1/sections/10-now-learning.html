The ideas I work with

  • Memory coalescing

    Neighbouring threads read neighbouring addresses, so the GPU fetches one wide block instead of many small ones.

  • Tiling and shared memory

    Load a small tile of data once into fast on-chip memory, then reuse it many times.

  • Warps and occupancy

    Threads run in groups called warps. Keep enough of them in flight to hide memory waits.

  • Roofline

    Count FLOPs per byte. It tells you if a kernel is limited by maths or by memory.

  • Quantization

    Store weights in int8, fp8 or 4-bit. Fewer bytes to move, so the same card runs bigger models faster.

  • Serving

    vLLM, llama.cpp and MLX. Turning a model file into a server that answers many requests well.

  1. Step 1 / Model

    A model is mostly weights. On my 4090 they sit in 24 GB of VRAM. Every token has to read them, so bytes moved set the pace.

  2. Step 2 / Kernel

    A kernel splits the work into blocks and warps. Each block pulls a tile into shared memory and works on it in registers.

  3. Step 3 / Memory

    The roofline asks one question. Does this kernel wait on memory or on maths? Coalescing, tiling and quantization all move it up the roof.
